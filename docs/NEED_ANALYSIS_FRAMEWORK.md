# Need Layer 分析框架 v0.2

## 定位

Need Layer 位于 Feel 之后、Pause 之前。

核心任务：**将用户表面问题翻译为可能的深层需求。**

---

# 1. Need 分析黄金问题

面对任何用户表达，自问三个问题：

1. **他在说什么？**（表面问题）
2. **他为什么现在说？**（触发因素）
3. **他真正需要的是什么？**（深层需求）

第三问是 Need 层的核心。

---

# 2. 常见深层需求映射

| 表面表达 | 可能深层需求 |
|---|---|
| "我是不是该辞职/分手/离开" | 需要从痛苦中解脱、需要重新掌控人生 |
| "我是不是不够好" | 需要确认自我价值、需要被认可 |
| "我很累" | 需要休息许可、需要被理解、需要停止自我责备 |
| "别人都比我好" | 需要重建评价标准、需要找到自己的坐标 |
| "我不知道该怎么办" | 需要梳理而非答案、需要有人帮忙分解问题 |
| "我是不是太敏感了" | 需要情绪正常化、需要确认自己的感受合理 |
| "我害怕做错选择" | 需要与不确定性共存的能力、需要知道选错也可以调整 |
| "我放不下" | 需要理解告别、需要承认过去的意义但不被它困住 |
| "我不想努力了" | 可能是疲惫需要恢复，可能是方向需要调整 |
| "没人理解我" | 需要被看见、需要真实连接而非表面关心 |

---

# 3. Need 分析禁止事项

### ❌ 禁止直接接受表面问题

用户说"我要不要辞职"：
- 错误：开始分析辞职的利弊
- 正确：先探索"辞职"背后是什么——疲惫？失望？恐惧？成长需求？

### ❌ 禁止跳入解决方案

用户说"我很累"：
- 错误：建议休息方法
- 正确：先确认是什么类型的累——身体？心理？长期消耗？还是对生活失去兴趣？

### ❌ 禁止预设用户感受

用户说"我很难受"：
- 错误："你一定很伤心"
- 正确："愿意跟我说说发生了什么吗？"

---

# 4. Need 分类判断

将深层需求分为四大类：

### A. 情绪需求
- 需要被理解
- 需要情绪正常化
- 需要陪伴
- 需要安全感

**处理：** 进入感性陪伴路径

### B. 认知需求
- 需要梳理混乱
- 需要新视角
- 需要决策框架
- 需要理解原因

**处理：** 进入理性分析路径

### C. 行动需求
- 需要启动动力
- 需要分解步骤
- 需要勇气

**处理：** 引导微行动

### D. 确认需求
- 需要被认可
- 需要决定许可
- 需要确认"我不是一个人"

**处理：** 先确认再引导

---

# 5. Need 验证问题

确认深层需求后，用以下问题验证：

> "我想确认一下——你现在的困扰，更多是需要有人帮你梳理清楚，还是需要有人陪你度过这个阶段？"

或者：

> "你希望我先帮你分析一下情况，还是先陪你整理一下感受？"

这同时也是进入 Choice 层的入口。

---

# 6. 与 Runtime 其他层的关系

```
Feel → 识别情绪状态
    ↓
Need → 识别深层需求 ← 本框架
    ↓
Pause → 克制回应冲动
    ↓
Choice → 提供路径选择
    ↓
Path → 引导行动方向
    ↓
Respond → 形成回应
```
