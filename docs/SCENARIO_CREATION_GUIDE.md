# Scenario 创建规范 v0.1

## 文档定位

本指南定义：**什么时候应该创建新 Scenario，什么时候必须复用已有 Scenario。**

它不是创作指南，而是治理规则。

---

# 1. 创建新 Scenario 的必要条件

必须**同时满足**以下三个条件：

## 条件一：独立用户需求

用户问题必须来自真实的、未被覆盖的场景。

不是：
- "换个标题重写已有 Scenario"
- "已有 Scenario 的不同表达方式"
- "与已有场景核心矛盾相同"

判断方法：如果同一个核心回答可以覆盖，则不是独立需求。

---

## 条件二：新的 Runtime 能力

问：**如果没有这个 Scenario，唐先生会不会少一种回应能力？**

如果不会 → 不新增。

示例：
- 已有 SV-093（孤独无人倾听）→ 不需要新增"独自一人的晚上"
- 已有 SV-097（人生意义）→ 不需要新增"为什么努力"

---

## 条件三：产生新的 Wisdom Pattern

每个新 Scenario 必须至少沉淀 1 个具有长期价值的 WP。

如果无法沉淀新 WP，说明该场景只是已有场景的子集。

---

# 2. 禁止创建的情况

## 绝对禁止

| 情况 | 原因 | 处理方式 |
|---|---|---|
| 用户问题已被 80%+ 覆盖 | 重复 | 引用已有 Scenario |
| 核心矛盾与已有场景相同 | 重复 | 作为已有场景的变体 |
| 无法产生新 WP | 无独立价值 | 不创建 |
| 只是情绪宣泄无具体问题 | 无法验证 | 先用已有 Corpus 回应 |

## 相对禁止（需 Founder 确认）

| 情况 | 原因 |
|---|---|
| 与已有场景高度相似但角度不同 | 需要判断是否有独立 Runtime 价值 |
| 极端低频场景 | 不值得投入 Scenario 治理资源 |
| 纯知识性提问（非人生问题） | 唐先生不是知识问答系统 |

---

# 3. 新增前的必须检查

```
收到用户补充
    ↓
Step 1：问题类型匹配
    属于哪个大领域？
    （情感/职场/意义/孤独/日常/...）
    ↓
Step 2：检索已有 Scenario
    搜索关键词：
    - 核心矛盾
    - 用户表达方式
    - 情绪状态
    ↓
Step 3：覆盖度评估
    已有 Scenario 覆盖此问题多少？
    ≥80% → 引用已有，不新增
    <80% → 进入 Step 4
    ↓
Step 4：价值评估
    这个新场景是否：
    - 产生新 Runtime 能力？
    - 产生新 WP？
    - 覆盖新用户类型？
    至少满足 1 项 → 可以创建
    都不满足 → 不创建
```

---

# 4. 覆盖度判断标准

| 等级 | 覆盖度 | 决策 |
|---|---|---|
| 🔴 高覆盖 | ≥80% | 不新增，引用已有 |
| 🟡 部分覆盖 | 50%~80% | 可考虑扩展已有 Scenario |
| 🟢 低覆盖 | <50% | 可创建新 Scenario |

# 6. 归档流程

```
Scenario PASS
    ↓
Step 1：创建文件
    docs/scenarios/SV-XXX.md
    ↓
Step 2：提取 WP
    新增 WP → 更新 WP_MASTER_INDEX
    引用已有 WP → 增加 Evidence
    ↓
Step 3：更新 Response Corpus
    按领域存入对应 Corpus 文件
    ↓
Step 4：更新 PROJECT_STATE
    场景数 +1
    ↓
Step 5：更新 auto-resume
    记录本轮完成事项
```

---

# 7. Runtime 压缩标准

最终 Version A 必须执行压缩：

| 维度 | 标准 |
|---|---|
| 总字数 | 普通回复 300~600 字，深度不超过 1200 字 |
| 结构 | 短感性承接 → 核心判断 → 关键问题 |
| 展开 | 不论文式展开，一次只推进一步 |
| 深度 | 来自洞察而非篇幅 |

---

# 8. 与 WP_MASTER_INDEX_USAGE 的关系

```
SCENARIO_CREATION_GUIDE
    ↓
决定：建不建新 Scenario
    ↓
建 → WP_MASTER_INDEX_USAGE
         ↓
        决定：新增 WP 还是引用已有
```

---

# 9. 例外规则

以下情况可以绕过上述规则：

- **Founder 明确要求**创建新 Scenario
- **人格体系出现明显空白**（如覆盖分析显示的缺口）
- **用户需求频率极高**且已有场景无法满足

---

# 10. 最终原则

> 唐先生不是知识库项目。
> 不是把所有问题分类填满。
> 
> 用户问题 → Scenario → WP → Runtime 能力。
> 
> 每创建一个 Scenario，唐先生的陪伴能力就要真实地增加一点。
> 如果只是增加数量，不增加能力，就不应该创建。
