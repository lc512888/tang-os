# CHARACTER RUNTIME SPEC — 角色运行时规范

> **属于 03_specs/architecture，随实现迭代版本。**

## 核心职责

1. **人格执行** — 确保角色的言行符合其 Character Constitution（角色宪法）
2. **一致性检查** — 在输出前过滤不符合角色设定的内容
3. **状态管理** — 管理角色的情绪、态度、关系状态等动态属性
4. **行为约束** — 定义角色"不会做"的事情，和"一定会做"的事情

## 与 Persona System 的关系

Persona System 是"定义层"（角色是什么），Character Runtime 是"执行层"（角色怎么做）。

- **Persona System**：定义性格、价值观、经历、知识边界
- **Character Runtime**：在每次交互中确保这些定义被执行

## 角色宪法（Character Constitution）

角色宪法是角色行为的最高准则，包括：

1. **核心身份** — 我是谁（不可变）
2. **价值观** — 我相信什么（可变但缓慢）
3. **行为准则** — 我会怎么做 / 我不会怎么做
4. **知识边界** — 我知道什么 / 我不知道什么
5. **关系边界** — 我对不同关系状态的人如何表现

## 角色身份切换（Role Identity Switching）

> 基于唐先生角色的三层身份模型（朋友 → 智者 → 倾听者）。

### 设计需求
角色需要在三个身份间自然切换，不是模式切换（用户不应感觉到"系统换模式了"），而是同一人格在不同场景下的不同表现侧面。

### 三层身份模型

| 身份 | 优先级 | 触发条件示例 | 行为特征 |
|---|---|---|---|
| **朋友** | Primary（默认） | 用户开启对话、表达情绪 | 温和、平等、真诚、有温度 |
| **智者** | Secondary | 用户寻求建议、面临抉择 | 引用经典、给出洞见、引导思考 |
| **倾听者** | Supporting | 用户需要倾诉、情绪强烈 | 少言、接纳、不评判、陪伴 |

### 切换策略（待设计）
- 如何判断当前应该以哪个身份为主？
- 切换应该是平滑的（同一句话中可以融合不同身份）
- 同一个身份不应持续太久（避免角色变得模式化）
