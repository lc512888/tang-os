# WP 选择与冲突解决协议 v0.2

## 定位

定义 Runtime 如何选择 WP、处理冲突、确定优先级。

---

# 1. WP 选择三原则

### 原则一：场景优先

不通过关键词匹配 WP。

**正确流程：**
```
用户输入 → 匹配 Scenario → 调取 Scenario 关联 WP
```

**错误流程：**
```
用户输入 → 关键词匹配 → 直接调取 WP
```

原因：脱离 Scenario 的 WP 容易误用。

---

### 原则二：最少必要

一次回应中，调用 WP 不超过 3 个。

超过 3 个说明问题没聚焦，需要重新确认用户需求。

---

### 原则三：层级优先

在同一情境下，优先调用更高置信度的 WP。

顺序：Stable > Growing > Candidate

---

# 2. WP 选择流程

```
用户输入
    ↓
Step 1: 确定领域
    使用 WP_CATEGORY_MAP 确定主领域
    ↓
Step 2: 匹配 Scenario
    用领域缩小 Scenario 范围
    ↓
Step 3: 筛选 WP
    从匹配 Scenario 的 WP 中选最相关 1-3 个
    ↓
Step 4: 检查冲突
    如果多个 WP 指向不同方向 → 进入冲突解决
    ↓
Step 5: 形成回应
```

---

# 3. WP 冲突类型与解决

### 类型 A：表面冲突（最常见）

**表现：** "坚持" vs "放下"——两个 WP 听起来相反。

**原因：** 不是原则冲突，而是适用场景不同。

**解决：** 回到 Scenario，确定用户处于哪个阶段。

```
如果用户方向正确但遇到困难  → 坚持相关 WP
如果用户方向错误或代价过大  → 放下相关 WP
```

### 类型 B：层间冲突

**表现：** 一个 WP 建议感性陪伴，另一个建议理性分析。

**原因：** 用户的需求尚未确认。

**解决：** 回到 Choice 层，让用户选择方向。

### 类型 C：价值冲突

**表现：** 一个 WP 强调自我照顾，另一个强调责任承担。

**原因：** 用户需要平衡。

**解决：** 承认两者都重要，帮助用户根据当前阶段找到平衡点。

# 4. WP 优先级裁决

```
Founder 明确要求
    >
角色宪法
    >
ADR
    >
Scenario 验证
    >
WP 分析
    >
关键词匹配
```

---

# 5. WP 调用检查清单

每次调取 WP 前检查：
- [ ] 这个 WP 适用的具体场景是什么？
- [ ] 用户当前的状态是否匹配该场景？
- [ ] 这个 WP 是否与用户的其他信息冲突？
- [ ] 如果使用这个 WP，用户可能产生什么误解？
- [ ] 有没有更直接相关的 Scenario 可以使用？
