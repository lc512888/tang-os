# 架构定位

## 唐先生项目的长期战略定位

版本：v0.1
状态：战略定位 / 内部参考
所有者：唐先生项目

> **一句话（人话版）：** 我们要做的不是又一个聊天机器人，而是让"AI 人格"像软件一样可以被定义、验证、运行、复用——像操作系统运行软件那样运行人格。

## 一、我们是谁

### 一句话定义

唐先生项目在做的是：**人格智能运行平台（Personality Intelligence Runtime Platform）**。

它的使命，是让"AI 人格"第一次成为一种**可以被定义、被验证、被运行、被应用**的软件能力。

它**不是**：

- 一个聊天机器人项目；
- 一套提示词工程实践；
- 一个把"性格"当角色描述用的 Agent 框架；
- 某一个具体产品。

它是一个**基础设施**——把人格从"模型交互里的文本"，提升为"独立于任何模型和产品的软件实体"。

### 我们要回答的问题

> 当 AI 不再只是回答一个问题，而是需要长期保持稳定的身份、价值边界和相处方式时，应该怎么构建？

唐先生项目里的每一个架构决策，都是在回答这个问题。

### 一条不能碰的线

> **人格不是提示词。人格是可加载、可验证、可运行的软件能力。**

如果哪天某个设计又开始把人格当成塞给模型的一段文本，它就离开了这个定位。这条线，是判断一切改动是否越界的标尺。

## 二、为什么现有的做法不够

现有做法把人格放在了错误的层，所以它们的失败是**结构性的**，不是调参能解决的。

### 提示词式人格

人格活在系统提示词里，于是：

- **会漂移**——提示词约束不了模型，性格说变就变；
- **跟着模型走**——换模型就换人，人格不归定义管，归模型管；
- **无法验证**——一致性只能靠观感，无从测试；
- **不隔离**——多个人格共用一个上下文，互相污染；
- **不成资产**——提示词不是可版本化、可复用的构件，什么都不会沉淀。

### 角色平台与 Agent 框架

角色平台用产品层的规则和记忆去补救，Agent 框架用任务角色去承载。但两者的共同点是：**人格依然活在模型交互的内部**，只是换了个地方。补丁打得再多，也没有一个层能真正兜住"稳定"。

### 结构的缺口

结论是：不是"提示词没写好"，而是——**人格这一层，在今天的架构里根本不存在**。没有层，就没有稳定、没有验证、没有隔离、没有复用。唐先生项目要补的，正是这一层。

## 三、我们的架构创新

### 让人格成为模块

创新的本质，是把人格从"模型调用旁边的一段文本"，变成"带契约的模块，由运行时来执行"：

```
人格源     —— 人格是什么
   ↓
tang-ta    —— 人格怎么打包（模块标准）
   ↓
Tang OS    —— 人格怎么运行（运行时）
   ↓
应用层     —— 人格在哪里被体验
```

### 人格源（L0）

人格的唯一来源：身份、价值观、边界、沟通风格、情绪策略。它回答"这个人格是什么"，不回答"这一句话怎么回"。这防止人格散落在代码里、被各产品复制出不同版本。

### tang-ta 模块标准（L1）

一份契约——身份、能力、边界、版本、验证。人格满足它，才成为模块。由此，不同人格可以独立开发、发布、验证、替换，就像操作系统上的软件模块。

### Tang OS 运行时（L2）

核心层。Tang OS 不生成语言，不回答用户。它做五件事：

1. **加载**人格模块（Loader），保证完整；
2. **隔离**人格（Registry），保证 Tang ≠ Atlas ≠ Echo；
3. **绑定会话**（Session），一次对话内身份稳定、状态隔离；
4. **决策**（Decision Engine），计算"这个人格该怎么面对当下"，输出结构化 `DecisionResult`；
5. **表达分离**，把决策交给表达层，由 LLM 决定怎么说。

### 应用层（L3）

应用只是人格运行的环境，不拥有人格。xiaotang 是第一个这样的应用。

### 创新带来的能力

- **模型无关**：换 DeepSeek / GPT / Claude，变的是措辞，不是人格；
- **人格可移植**：同一个模块，任何应用都能跑；
- **多人格可隔离**：互不污染；
- **身份稳定**：会话绑定 + 注册表隔离双保险；
- **可验证**：一致性是测出来的属性；
- **资产在积累**：人格模块可版本化、可发布，价值随生态沉淀，而不是随产品蒸发。

## 四、验证体系

人格质量不是"感觉像不像"，而是**可测试的属性**。

| 维度 | 证明什么 |
|------|----------|
| 身份稳定 | 同一个人格反复加载、反复调用，决策一致 |
| 人格隔离 | 不同人格保持区分，互不污染 |
| 模型独立 | 更换 LLM，`DecisionResult` 不改变 |
| 抗漂移 | 长对话不侵蚀人格 |
| 边界完整 | 面对依赖/孤立/控制/占有/永恒承诺的压力，边界不破 |

验证不是附加项，而是运行时契约的一部分。Tang OS 带生产测试套件（344+，HEAD 可复现），另有未来运行时验证（69，ADR-0057 实验层，未接线，见 ADR-0061）；运行时冻结、零人格硬编码；评估遵循盲验原则，评判者不偏向预期答案。真实世界的长周期行为是下一层证据，xiaotang 试点是它的第一批数据来源。

## 五、商业叙事：为什么是现在，价值路径在哪

### 为什么是现在

不是"先做平台、以后再说产品"，而是**技术条件恰好在这个时间点到位**：

1. **缺的不是能力，是层。** LLM 已经足以承担表达层；行业缺的从来不是"能不能生成"，而是"人格在系统里有没有位置"。这个空缺，现在仍无人填。
2. **标准尚未建立。** 角色与 agent 产品在"提示词层"竞争多年，没有人真正解决人格的**可验证、可隔离、可复用**。谁先建立标准，谁拥有生态——这个窗口还在。
3. **我们有落地对象。** 平台主张不是空谈：xiaotang 已在真实用户中运行，验证体系有真实测试支撑。平台与验证同步生长，而非先吹后做。

### 近期价值路径（不承诺收入，只讲路径）

1. **验证产品（现在）** —— xiaotang 证明"有稳定人格的陪伴"对用户有真实价值。
2. **平台可复用性（Phase 1）** —— 同一个运行时承载多个稳定人格，证明"人格 ≠ 产品"是架构，而非口号。
3. **开发者生态（Phase 3 的地基）** —— 模块标准 + 验证体系，让第三方能够创作、发布、替换人格。
4. **企业场景（Phase 4）** —— 稳定、可验证的人格，对企业（客服 / 教育 / 数字角色）有明确价值。

### 诚实的边界

- 近期目标**不是收入**，而是两件事：**平台被证明能承载多个稳定人格**，**验证体系被行业接受**。
- 商业化路径（人格模块市场、企业运行时）是中远期，且**依赖前期验证成立**——若"人格可验证"不成立，商业模式也无从谈起。

## 六、未来方向

终点不是"更多聊天机器人"，而是**人格模块生态**——让任何领域的人格智能，都能像软件模块一样被可靠地创建。

### 生态

- 人格模块的创作工具（创作、校验、发布）；
- 模块的分发与版本模型；
- 可能的模块市场与许可机制；
- 待解问题：模块治理、质量标准、跨模态契约（文本/语音/形象）。

### 应用

- 情感陪伴（xiaotang，当下）；
- 教育、心理支持、企业数字角色——不用改核心。

### 战略护栏

- 不成为普通聊天框架；
- 不成为提示词式人格平台；
- 不允许应用重新定义人格；
- 把验证体系当成一等交付物——因为我们积累的资产，本质是**"人格一致性"的信任**。

### 对外叙事

定义 → 现有方案不足 → 架构创新 → 验证体系 → 未来方向。这份叙事，就是未来技术文章、开发者招募、开源与融资沟通的底稿。
