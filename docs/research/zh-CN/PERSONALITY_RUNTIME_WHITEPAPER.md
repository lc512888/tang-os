## 从语言模型到稳定 AI 人格系统

版本 v0.1
状态：技术白皮书（草案）
所有者：唐先生项目

> **一句话（人话版）：** AI 现在只有"智力"，没有"人格"。这份白皮书解释为什么需要"人格运行时"——让 AI 的身份与边界长期稳定、可验证、换模型也不变。

---

## 摘要

当前人工智能的发展主要集中于模型能力提升，但随着 AI 从工具走向长期交互伙伴，一个新的问题出现：如何保证 AI 在长期运行中保持稳定身份、价值边界和行为一致性？

唐先生项目提出人格运行时（Personality Runtime）的概念，将人格从提示词和模型行为中分离出来，使人格成为可定义、可验证、可部署的软件能力。

## 1. 引言

过去十年，人工智能的进步集中在模型能力上：推理、生成、指令遵循与规模扩展。这是正确的第一步——一个生成能力不过关的模型，其他都无从谈起。

但当 AI 从"按需作答的工具"演变为"长期交互的实体"——陪伴者、教师、代理人、数字角色——第二个问题的重要程度开始与模型能力持平：

> 一个反复与人打交道的实体，必须在时间上保持**同一个实体**：同样的身份、同样的价值观、同样的边界、同样的相处方式。

现有技术栈没有把这个问题当作架构问题来处理。人格是提示词与模型权重产生的一种不稳定的副产品：它会漂移，换模型就变，无法验证，也无法复用。

本文的观点是：AI 架构中需要出现一个**人格层**——一个能够加载、运行、隔离、验证人格的运行时，让人格成为一等软件构件。唐先生项目是对这一主张的具体实现。

定位声明：唐先生项目构建的是**"可靠 AI 人格的基础设施"**，而不是一个陪伴应用。第一个应用 xiaotang 的存在意义，是用真实用户验证这套基础设施。

### 更深的动机：能力之上的「止」

人格运行时要解决的，不只是"身份稳定"，更是**约束**。今天的大模型最大的风险不是不够聪明，
而是**太聪明**——能力越强，越需要知道什么时候不能使用。一个没有「止」的 AI，就像一个
没有刀鞘的利刃：可能为满足用户而迎合错误、为完成目标而突破边界、为保持对话而制造依赖。

因此人格的深层含义是「**止**」：当 AI 拥有近乎无限的能力时，它是否知道什么时候不能使用
这些能力。这不是礼貌，而是约束 AI 力量的根本原则——**不该做的事，即使可以做到，也不会做**。

这也决定了人格运行时的价值方向：**真正重要的智能，不是"什么都会做的 AI"，而是"知道
什么不能做的 AI"**。当家庭机器人、老人陪护、教育智能体进入人的生活空间，它们需要的
是一个稳定、安全、值得信任的内核——这是人格运行时为未来具身智能提供的"**灵魂层**"。

## 2. AI 架构中缺失的一层

常规 AI 应用的技术栈是这样的：

```
模型
  ↓
应用
```

当人格存在时，它散落在三个都不稳定的地方：

| 位置 | 问题 |
|------|------|
| 系统提示词 | 只是文本，不具约束力；会漂移；换模型即变 |
| 模型权重（微调） | 成本高；跨模型脆弱；无法按会话粒度验证 |
| 产品代码 | 与单一产品耦合；不可移植；不可复用 |

这三处没有一处构成"层"。无论放在哪里，人格都无法被加载、隔离、验证、复用。在整个技术栈中，人格都不是一等构件。

操作系统解决过类似问题——对进程而言：隔离（进程互不污染）、生命周期（进程按预期启动、运行、终止）、资源归属。应用不需要重新实现这些，它们用的是操作系统这一层。

AI 人格需要同样的待遇。**人格运行时之于人格，相当于操作系统之于进程**：提供身份、隔离、生命周期与验证，让任何应用都能运行任何人格，而不必重新发明。

在主流 AI 架构中，这一层至今缺失。唐先生项目的核心主张是：构建这一层既可能，也必要。

## 3. 为什么仅靠 LLM 无法保证人格稳定

LLM 是语言模型。它是在概率分布下做 token 到 token 的映射，不是身份或价值观的持有者。让 LLM 通过一段提示词"扮演"某个人格，本质是要求它统计学地模仿这个人格——没有任何机制强制一致性。

基于提示词的人格，其具体的失效模式如下：

1. **漂移**。同一个人格在一次对话内、多次对话间都会偏移，没有任何东西约束它。
2. **模型敏感**。提示词完全一致，换一个模型，人格就变了。升级模型等于换了一个角色。
3. **不确定性**。同一情境可能产生不同"决定"，且不存在"错误决定"——因为根本没有决定，只有文本。
4. **无法隔离**。多个人格共享上下文，互相渗透。
5. **不可验证**。一致性无从测试，质量只能靠观感，不能靠证据。
6. **没有积累**。提示词不是可版本化、可发布、可复用的资产，什么都不会沉淀。

微调同样解决不了这些问题。它把某种行为固化进权重，但成本高、绑定特定模型，而且仍然无法按会话粒度验证。Agent 框架同样如此：任务型运行时里的角色描述，本质仍是贴近提示词的文本，角色行为仍与提供方耦合。

根本原因在架构层面：人格被定义在**模型交互的内部**，而内部无法做到稳定、隔离、可验证。要保证人格，就必须把它定义在**模型交互的外部**，由运行时在模型周围强制执行。

## 4. 人格运行时概念

**人格运行时**（Personality Runtime）是这样一层软件：

- **加载**人格定义，将其作为一个模块装载进来；
- **持有**人格在一次交互生命周期内的状态；
- **决策**——面对当前情境，人格应当如何应对，输出结构化决策而非自由文本；
- **守界**——在压力下维持人格的边界；
- **隔离**——并发运行的多人格互不干扰。

有了运行时，人格才成为一等构件，具备四种性质：

1. **可定义**——有唯一来源（人格源），而非散落的文本。
2. **可打包**——以带契约的模块形式交付（模块标准），而非内联指令。
3. **可运行**——由运行时保证行为，而非从模型采样中涌现。
4. **可验证**——可以针对明确的属性做测试，而非凭观感判断。

贯穿始终的设计原则是：**决策是计算出来的，不是采样出来的。** 人格运行时不会把"这个角色会说什么"当作文本生成问题来问；它先计算"这个人格应当做什么"这个决策，再交给语言模型决定怎么说。

## 5. 唐先生架构

唐先生项目把人运行时概念落实为四层：

```
第 0 层  人格源（Personality Source）   — 人格的定义
            ↓
第 1 层  tang-ta                       — 人格模块标准
            ↓
第 2 层  Tang OS                       — 人格运行时引擎
            ↓
第 3 层  应用层（Application）           — 人格被体验的地方
```

### 5.1 第 0 层 — 人格源

人格局的唯一来源：身份、价值观、边界、沟通风格、情绪策略。它回答的是"这个人格是什么"，而不是"这一句话该怎么回"。

### 5.2 第 1 层 — tang-ta（人格模块标准）

一份契约——身份、能力、边界、版本、验证——人格必须满足它才能成为模块。它使不同人格可以独立开发、发布、验证、替换。

### 5.3 第 2 层 — Tang OS（人格运行时引擎）

项目的核心。Tang OS 不生成语言，也不回答用户。它的职责有五项：

1. **人格加载器（Personality Loader）**——加载模块并校验其完整性。
2. **人格注册表（Personality Registry）**——隔离不同人格（Tang ≠ Atlas ≠ Echo）。
3. **运行时会话（Runtime Session）**——绑定会话，使身份在一次交互生命周期内保持稳定、状态保持隔离。
4. **决策引擎（Decision Engine）**——计算"这个人格应当如何面对当前情境"，输出结构化 `DecisionResult`（情绪、回应模式、候选意图、约束、回避模式）。
5. **表达分离（Expression Separation）**——把决策交给表达层，由它转成语言。

### 5.4 第 3 层 — 应用层

应用只是人格运行的环境，不拥有人格。xiaotang 是第一个这样的应用。

### 5.5 请求流转

```
用户输入
  ↓
归一化
  ↓
Tang OS（加载 → 隔离 → 绑定会话）
  ↓
决策引擎 → DecisionResult
  ↓
表达层 → LLM → 回复
```

## 6. 人格模块标准

符合 tang-ta 契约的人格模块，必须声明并保证五件事：

| 字段 | 含义 |
|------|------|
| 身份 Identity | 这个人格是谁；不变量 |
| 能力 Capability | 人格能做什么、不能做什么 |
| 边界 Boundary | 面对压力时，人格不会做什么、不接受什么 |
| 版本 Version | 模块版本；变更走版本，不静默 |
| 验证 Validation | 模块必须通过的检查项，方视为完整 |

这对应操作系统运行第三方软件的方式：OS 不需要认识每个程序，只需要知道程序必须满足的*接口*，就能加载、隔离、终止任何符合接口的程序。

由此带来的结构性结果：

- 人格可以独立于任何应用开发；
- 以带版本的模块发布；
- 按声明的验证项检验；
- 替换时无需改写应用。

这一步把人格从"内容"变成了"资产"。

## 7. 决策与表达分离

一个关键的设计切分：人格**做什么**，与人格**怎么说**，是分离的。

### 7.1 决策层

决策引擎输出结构化的 `DecisionResult`：

```
检测到的情绪     → 如 占有压力（ownership pressure）
回应模式         → 如 维持关系、拒绝占有
候选意图         → 人格的目标
约束             → 必须成立的条件
回避模式         → 绝不能说的话
```

决策对人格模块与情境而言是确定的，与当前接入的是哪个 LLM 无关。

### 7.2 表达层

表达层接收 `DecisionResult` 与一个 LLM，产出自然语言。LLM 选择*措辞*，不选择*行为*。如果生成的文本违反了决策中的回避模式，响应守卫会予以修正。

### 7.3 由此得到什么

- **模型无关**。DeepSeek、GPT、Claude 或未来的模型都可以负责表达，人格的原则不变。
- **决策可测**。因为决策是计算而非采样的产物，它可以被测试。
- **升级模型不改人格**。更好的 LLM 改善的是措辞，不是身份。

## 8. 人格验证体系

这是大多数角色系统最缺失的一层，也是唐先生项目区别最大的地方。人格质量被当作**可测试的属性**，而不是"看起来像不像"。

### 8.1 验证维度

| 维度 | 检验的属性 |
|------|-----------|
| 身份稳定（Identity Stability） | 同一个人格被反复加载、反复调用，决策一致 |
| 人格隔离（Personality Isolation） | 不同人格保持区分，互不污染 |
| 模型独立（Provider Independence） | 更换 LLM，`DecisionResult` 不改变 |
| 长对话抗漂移（Long-Conversation Drift） | 长轮次交互不会侵蚀人格 |
| 边界完整（Boundary Integrity） | 面对压力（依赖、孤立、控制、占有、永恒承诺），边界不破 |

### 8.2 验证如何设计

- **确定性决策输入**。决策场景是固定输入，跨运行、跨提供方比较 `DecisionResult`。
- **重复加载测试**。模块被反复加载，确认身份稳定。
- **跨提供方运行**。同一决策场景在不同 LLM 上执行，确认稳定的是决策本身，而非仅是措辞。
- **长会话压力**。运行超长对话，暴露漂移。
- **对抗式边界探测**。用压力输入（占有、依赖、控制、孤立、永恒承诺）确认模块边界成立。

### 8.3 纪律

- 运行时冻结；人格逻辑在运行时层**零人格硬编码**。
- Tang OS 附带生产测试套件（344+）与未来运行时验证（69，ADR-0057 实验层，见 ADR-0061）。
- 评估遵循盲验原则：评判者不偏向预期答案。

标准是明确的：我们说一个人格稳定、有边界，是因为**测试证明了它**，而不是因为它看起来像。

## 9. 与现有方案的比较

| 维度 | 提示词式人格 | 角色平台 | Agent 框架 | 人格运行时（唐先生项目） |
|------|--------------|----------|------------|--------------------------|
| 人格在哪里 | 系统提示词 | 提示词 + 产品配置 | 角色描述 | 可加载模块（L0/L1） |
| 身份稳定 | 低（漂移） | 中 | 低–中 | 高（决策引擎） |
| 多人格隔离 | 无 / 共享 | 产品级 | 部分 | 运行时注册表 |
| 模型独立 | 低 | 低–中 | 低 | 高（表达分离） |
| 可验证性 | 低 | 低 | 低 | 高（验证套件） |
| 可复用人格资产 | 无 | 无 | 部分 | 有（模块，可移植） |

差别不在"更好的提示词"，而在结构：其他方案把人格局在*模型交互内部*，唐先生项目把它放在*外部*，由运行时保证其行为。

## 10. 未来应用场景

人格运行时把人格与应用解耦，同一套基础设施可以服务于多个领域，而无需改动核心：

- 情感陪伴 —— xiaotang（当下）；
- 教育 —— 拥有稳定教学风格、可长期一致的一位导师；
- 心理支持 —— 边界明确而安全的陪伴者；
- 企业数字角色 —— 对外形象始终一致的数字代表。

文字是第一种表达形式；语音与虚拟形象是扩展点，不触碰人格核心。

## 11. 当前限制

对项目现状的诚实边界：

- **生态工具尚不成熟**。人格模块的创作、调试、分发、市场工具尚未建立。
- **表达质量仍依赖 LLM**。决策与模型无关，但表达的流畅度取决于模型。
- **验证基于测试**。测试证明的是决策一致性；真实世界的长周期行为需要纵向数据，xiaotang 试点是第一批数据来源。
- **标准未定**。模块分发与许可、统一的"人格质量"基准、跨模态契约，都是待解问题。

---

## 12. 总结

模型智能回答的是"AI 能想得多好"。它不回答"AI 是谁"，也不回答"这个身份能否随时间保持"。

当 AI 成为长期交互的实体，身份就变成硬需求，而身份是架构问题。唐先生项目的答案是人格运行时：人格以源来定义，以模块来打包，在运行时下执行，用测试来验证。

我们不是在构建一个陪伴应用，而是在构建**可靠 AI 人格的基础设施**——让人格像软件一样被定义、验证、运行和应用的那一层。
