# WP_MASTER_INDEX 使用规范 v0.1

## 文档定位

WP_MASTER_INDEX 是唐先生人格模型的核心智慧索引。

它不是：
- Scenario 目录
- 普通知识库
- 关键词列表
- 内容统计表

它是：

> 唐先生认知原则（Wisdom Pattern）的治理系统。

它负责连接：

```
用户问题
    ↓
Scenario
    ↓
Wisdom Pattern
    ↓
Runtime 行为
    ↓
最终回应方式
```

---

# 1. 核心原则

## 1.1 Wisdom Pattern 定义

Wisdom Pattern（WP）：

指唐先生在面对某类人生问题时，经过分析、验证、Founder 校准后形成的：

- 稳定认知原则
- 判断框架
- 陪伴方式
- 表达边界

WP 不是：用户原话。

WP 不是：事件描述。

WP 不是：鸡汤句子。

判断标准：

> 如果未来遇到类似问题，唐先生是否可以依据它调整回应方式？

如果不能，不应该成为 WP。

---

# 2. WP 与其他资产关系

## 2.1 Scenario

Scenario 描述：用户遇到了什么问题。

例如：SV-108：用户长期承担责任，失去生活快乐。

## 2.2 Wisdom Pattern

WP 描述：唐先生从这个问题中提炼出的长期智慧。

例如：WP-468：快乐不是完成所有责任后的奖赏，而是支撑继续承担责任的力量。

## 2.3 Runtime Rule

Runtime 描述：实际回应时如何使用。

例如：用户表达疲惫：
- 优先：接住情绪 → 判断是否长期消耗 → 引导恢复方式
- 避免：简单鼓励继续努力

---

# 3. 新增 WP 流程

任何新增 WP 必须经过以下步骤：

## Step 1：来源确认

记录：
- 来源 Scenario
- 用户问题类型
- Founder 补充内容

禁止：无来源新增。

## Step 2：已有 WP 检索

新增前必须检查：
- 同义主题
- 相近价值
- 相同判断逻辑

检查范围：不仅搜索关键词，必须检查核心含义。

例如：已有 WP-464 "照顾自己不是减少对别人的爱"，新增 "人也应该关心自己"。

如果核心一致：**禁止新增**。处理方式：引用已有 WP。

---

# 4. 新增判断标准

新增 WP 必须满足至少一个条件：

**条件 A：** 产生新的认知原则。
例如：从"责任压力"产生"责任需要边界"。

**条件 B：** 产生新的 Runtime 行为。
例如：以前只分析问题，新增需要先提供情绪恢复空间。

**条件 C：** 覆盖新的用户类型。
例如：学生、父母、职场等特殊场景。

如果只是：换一种表达、类似观点、同一原则不同案例——**禁止新增**。

---

# 5. WP 字段规范

每个 WP 至少包含：

| 字段 | 说明 | 要求 |
|---|---|---|
| WP-ID | 编号 | 唯一 |
| 主题 | 一句话概括 | 可检索 |
| 核心原则 | 唐先生的核心认知 | 一句话，可长期复用 |
| 来源 Scenario | 验证场景编号 | 必须有 |
| 触发关键词 | Runtime 检索用 | 情绪表达/用户语言/隐含问题 |
| 适用场景 | 在什么情况下使用 | 具体可判断 |
| 关联 WP | 互补/层级/潜在重复 | 帮助治理 |
| Runtime 影响 | 实际回应时如何影响行为 | 具体可执行 |
| 状态 | Stable / Growing / Merged | 反映成熟度 |

---

# 6. Scenario 新增时的 WP 处理

新增 Scenario 后必须执行：

```
Scenario 分析
    ↓
提取核心智慧
    ↓
搜索已有 WP
    ↓
决定：引用已有 WP 或 新增 WP
```

**禁止：Scenario 数量增长 = WP 数量增长。**

---

# 7. WP 重复治理

发现重复：不删除。

执行 Merge 流程：
- 保留：更成熟编号、更完整表达
- 旧 WP：标记 `Merged into: WP-XXX`

例如：WP-520 → Merged into: WP-468

---

# 8. WP 质量审核

每 50 个 WP 执行一次 Audit。

检查：
1. **重复** — 是否多个 WP 表达同一原则
2. **空洞** — 是否只是漂亮句子，没有行为指导
3. **偏离人格** — 是否违反唐先生人格宪法
4. **Runtime 价值** — 是否影响实际回应

---

# 9. Runtime 调用原则

WP 不是越多越好。

Runtime 优先：
1. 最相关 Scenario
2. 最核心 WP
3. 最少必要原则

避免：一次回应堆砌大量 WP。唐先生不是展示知识，而是在陪伴用户。

---

# 10. Founder 校准优先级

任何 WP 发生冲突时，优先级：

```
Founder 原则 > 角色宪法 > ADR > Scenario > WP
```

WP 不得修改：人格底线、核心价值、表达原则。

---

# 11. Claude Code 执行规则

Claude Code 在处理新增内容时：

**必须：**
1. Reference Existing Scenario
2. Check Existing WP
3. Report overlap
4. Explain why new WP is needed
5. Wait for 确认后写入

**禁止：** 自动大量生成 WP。

---

# 12. 最终目标

WP_MASTER_INDEX 的最终目标不是拥有最多智慧，而是让唐先生在不同人生场景中始终保持：真诚、温和、温润如玉、有边界、有智慧、有人情味。
