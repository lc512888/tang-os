# WP 迁移验证协议 v0.1

## 定位

本协议定义：当 WP 进行批量格式升级或迁移时，必须执行的验证流程。

---

# 1. 核心铁律

**AI 执行报告 ≠ 完成证明。**

完成证明必须包含：
1. 实际文件变化记录
2. Diff 检查（新旧对比）
3. 随机抽样复核（样本率 ≥ 20%）
4. 反向检索验证（WP → Scenario）
5. 回归测试（已有场景不受影响）
6. Founder 确认

---

# 2. 迁移前检查

- [ ] 目标格式已冻结（字段名、字段顺序、必填字段）
- [ ] 新旧格式对照表已生成
- [ ] 抽样样本已确定（至少 20%）
- [ ] 回归测试集已准备
- [ ] 语义保持标准已明确

---

# 3. 迁移中检查

每完成一批（不超过 150 个 WP）：
- [ ] 格式一致率 = 100%
- [ ] 语义保持率 = 100%
- [ ] 无幻觉新增（字段内容非凭空生成）
- [ ] 无字段遗漏（必填字段全部迁移）
- [ ] Misuse Prevention 字段未丢失

---

# 4. 迁移后验证

## 4.1 格式检查
- 随机抽取 ≥ 20% 的 WP，逐字段检查格式

## 4.2 语义检查
- 旧版核心原则 vs 新版核心原则 → 语义是否一致
- 如有任何"altered"标记 → 停止，人工复核

## 4.3 反向检索
- 对每个迁移后的 WP，验证其关联 Scenario 是否存在且正确

## 4.4 回归测试
- 对迁移涉及的 Scenario 运行回归测试
- 确保 WP 升级不改变 Scenario 行为

---

# 5. 发现问题处理

| 问题类型 | 严重程度 | 处理方式 |
|---|---|---|
| 格式错误 | 中 | 修正后继续 |
| 字段遗漏 | 高 | 停止迁移，补齐后重验 |
| 语义改变 | 严重 | 停止，人工复核后决定 |
| 幻觉新增 | 严重 | 停止，删除幻觉内容 |
| WP→Scenario 错配 | 高 | 停止，修正映射 |

---

# 6. 完成标准

- [ ] 格式一致率 = 100%
- [ ] 语义保持率 = 100%
- [ ] WP→Scenario 准确率 ≥ 95%
- [ ] 人格漂移 = 0
- [ ] 幻觉新增 = 0
- [ ] Founder 确认
