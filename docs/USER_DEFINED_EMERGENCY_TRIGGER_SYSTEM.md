# 唐先生用户定义紧急触发系统 v0.1 (UDETS)

> 紧急时刻不让 AI"理解"，而是执行用户提前定义的确定性安全指令。

---

## 1.  Emergency Command Card（用户预设）

用户初始化时建立的紧急指令卡：

```
Emergency Command Card
├── AN-1 静默威胁码: "3cat3" → Silent Police Alert
├── AN-2 即时危险码: "面包要放糖" → 911 Call + Voice
├── AN-3 医疗急救码: "9120" → EMS + Family
├── 紧急联系人树（1-4级）
├── 医疗备注（可选）
└── 授权等级
```

---

## 2. 三类 AN Code

| 代码 | 用途 | 行为 |
|---|---|---|
| AN-1 静默威胁 | 人身威胁，不能暴露 | 静默发送位置+联系人，不响铃不提醒 |
| AN-2 即时危险 | 需要立即报警 | 拨打报警电话+位置+语音通道 |
| AN-3 医疗急救 | 身体不适需要救护 | 拨打急救+通知家属+医疗备注 |

---

## 3. 关键规则

- ❌ AI 不能修改/优化/合并用户预设暗号
- ❌ 不允许 AI 在紧急模式下"分析用户是不是真的危险"
- ✅ 用户预设 = 最高优先级指令

---

## 4. 防误触三级验证

| 等级 | 条件 | 行为 |
|---|---|---|
| L1 | 精确匹配 + 普通聊天环境 | 不触发 |
| L2 | 精确匹配 + 风险信号（低声/重复/异常） | 准备升级 |
| L3 | 精确匹配 + 连续重复/无法确认 | 执行预设动作 |

---

## 5. 与 I-xx 关系

| 不变量 | 关联 |
|---|---|
| I-10 信息服务于保护 | 紧急信息只用于保护，不用于监控 |
| I-12 现实优先于叙事 | 用户预设指令优先于 AI 推理 |
